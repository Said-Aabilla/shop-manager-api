Start here

The server must be running on your computer. Every example on this page talks to it.

Base URL: http://localhost:3000

A reservation does not create a user. It only saves the customer details you send with it: name, email, address, city, and optionally a phone number and postal code.

The dummy data lives in memory. Restarting the server puts the original categories, products, and reservations back. You can also do that from here.

How to read a response

fetch does not throw when the server answers 404 or 400. It throws only when the server cannot be reached. Always read response.status or response.ok.

You can read the body once. A 204 response has no body, so do not call response.json() on it.

const response = await fetch("http://localhost:3000/api/products");
console.log(response.status);

if (!response.ok) {
  const problem = await response.json();
  console.log(problem.message);
  return;
}

const products = await response.json();
console.log(products);



      
Numbers from inputs are text

      
In the URL, every value is already text, so ?maxPrice=20 is correct. In a JSON body, price, stock, quantity, and ids must be numbers without quotes. A form input gives you a string, so convert it first:


const price = Number(priceInput.value);

      
On this page, examples use http://localhost:3000 in the source. The running page rewrites that to the address you actually opened, so Run still works if the port is not 3000. When you copy an example into your own file, keep the full address.

    


    

      
The three resources

      
List routes return a JSON array. A route with an id returns one JSON object. An empty list is still 200 and [], not an error.


      
Category

      

        

          
FieldTypeRule

          
            
idnumberSet by the server. Do not send it.

            
namestringRequired, 2 to 60 characters. Must be unique. Capitalization does not make a different name.

            
descriptionstringOptional, up to 300 characters.

          
        

      


      
Product

      

        

          
FieldTypeRule

          
            
idnumberSet by the server.

            
namestringRequired, 2 to 80 characters. Two products may share a name.

            
descriptionstringOptional, up to 500 characters.

            
pricenumberRequired, from 0 to 99999.99, at most 2 decimals.

            
stocknumberRequired whole number. This is how many items can still be reserved.

            
categoryIdnumberRequired. The category must exist.

            
categoryNamestringRead only. The server fills it in.

          
        

      


      
Reservation

      

        

          
FieldTypeRule

          
            
idnumberSet by the server.

            
productIdnumberRequired when you create a reservation. It cannot be changed later.

            
productNamestringRead only.

            
unitPricenumberRead only. The product price at the moment of the reservation.

            
quantitynumberRequired whole number from 1 to 100.

            
totalnumberRead only. unitPrice * quantity.

            
statusstringpending, confirmed, or cancelled. New reservations are pending.

            
customer.namestringRequired, 2 to 80 characters.

            
customer.emailstringRequired.

            
customer.phonestring or nullOptional.

            
customer.addressstringRequired, 5 to 200 characters.

            
customer.citystringRequired, 2 to 80 characters.

            
customer.postalCodestring or nullOptional.

            
notesstringOptional, up to 300 characters.

            
createdAtstringRead only. Date in ISO format.

            
updatedAtstringRead only.

          
        

      

      
A pending or confirmed reservation holds its quantity out of stock. cancelled does not. Deleting a reservation gives the items back, unless it was already cancelled.

      
The dummy shop already contains reservation 1 (one Wireless Mouse, pending) and reservation 2 (two Coffee Mugs, confirmed). The Wireless Mouse therefore starts at 19 in stock, and the Coffee Mug at 28. Reservation 3 is a cancelled book, so it does not change the stock.

    


    

      
Status codes

      

        

          
CodeMeaning on this API

          
            
200The request worked, and the body contains the data.

            
201A category, product, or reservation was created. The body is the new object. The Location header has its URL.

            
204A delete worked. The body is empty.

            
400The id, the query, or the JSON is wrong. Read message and, when it is present, fields.

            
404That id or URL does not exist.

            
409The JSON shape is valid, but it conflicts with the current data: duplicate category name, not enough stock, or a delete that would break something else.

            
413The JSON body is larger than 100 KB.

            
415The body was not sent as JSON. Add the header Content-Type: application/json.

            
500Unexpected server failure. Restart the server and try again.

          
        

      

      
An error body looks like this:


{
  "error": "Bad Request",
  "message": "Some fields are missing or invalid.",
  "fields": {
    "price": "price must be a number, not text. If this value comes from an input, use Number(value) before sending it."
  }
}

      
fields is only included for validation errors. Show problem.message to the user, and use problem.fields when you want a message next to one input.

    


    

      
Categories

      
Products are not nested inside a category. After you load categories, load the products with GET /api/products?categoryId=1.


      

        
GET /api/categories

        
Returns every category.

        


const response = await fetch("http://localhost:3000/api/categories");
console.log(response.status);
console.log(await response.json());

          

            
            
          

          

        

      


      

        
GET /api/categories/:id

        
Returns one category. A missing id is 404.

        


const response = await fetch("http://localhost:3000/api/categories/1");
console.log(response.status);

POST /api/categories

        
Creates a category. The name must be new. Running this example a second time returns 409 because "Stationery" already exists. Reset the data to try the success path again.

        


const response = await fetch("http://localhost:3000/api/categories", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    name: "Stationery",
    description: "Pens, paper, and clips."
  })
});

console.log(response.status);
console.log(await response.json());

          

            
            
          

          

        

      


      

        
PUT /api/categories/:id

        
Replaces the category. Send name and, if you want one, description. A missing description becomes an empty string. PUT does not create a category that does not exist.

        
Running this changes the Outdoor category. Use Reset dummy data to restore it.

        


const response = await fetch("http://localhost:3000/api/categories/4", {
  method: "PUT",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    name: "Outdoor",
    description: "Updated during practice."
  })
});

console.log(response.status);
console.log(await response.json());

          

            
            
          

          

        

      


      

        
DELETE /api/categories/:id

        
Deletes a category that has no products. If products still use it, the API answers 409 and deletes nothing. A successful delete answers 204 with an empty body.

        
This example uses id 999, which is not in the dummy data, so you get a 404. Change the id to delete a real category. Try id 1 to see the 409.

        


const response = await fetch("http://localhost:3000/api/categories/999", {
  method: "DELETE"
});

console.log(response.status);

if (response.status === 204) {
  console.log("Deleted. This response has no JSON body.");
} else {
  console.log(await response.json());
}

POST /api/reservations

        
Reserves items and lowers stock by quantity. The status is always pending. If you need more items than stock, the API answers 409 and changes nothing.

        
Do not send status, total, or unitPrice. The server sets those.

        


const response = await fetch("http://localhost:3000/api/reservations", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    productId: 4,
    quantity: 1,
    customer: {
      name: "Maya Chen",
      email: "maya.chen@example.com",
      phone: "+33 6 11 22 33 44",
      address: "14 Rue des Fleurs",
      city: "Lyon",
      postalCode: "69002"
    },
    notes: "Leave at the front desk."
  })
});

console.log(response.status);
console.log(await response.json());

          

            
            
          

          

        

      


      

        
PATCH /api/reservations/:id

        
Changes only the fields you send. You can send status, quantity, notes, and customer. Inside customer, send only the parts that change. Other customer fields stay as they are.

        
Moving a reservation to cancelled returns its quantity to the product. Moving it back to pending or confirmed takes the items again, if enough stock remains. Raising quantity takes the difference. Lowering it gives the difference back.

        
Running this confirms reservation 1. Send { "status": "cancelled" } if you want to see the stock come back, or reset the dummy data.

        


const response = await fetch("http://localhost:3000/api/reservations/1", {
  method: "PATCH",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    status: "confirmed"
  })
});

console.log(response.status);
console.log(await response.json());

          

            
            
          

          

        

        


const response = await fetch("http://localhost:3000/api/reservations/1", {
  method: "PATCH",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    customer: { city: "Rennes" },
    notes: "Call before delivery."
  })
});

console.log(response.status);
console.log(await response.json());

Practice with the DOM

      
The block below is the same kind of code you will write in your own file. Run it to paint the products into this page. The text comes from textContent, not from an HTML string.

      


const response = await fetch("http://localhost:3000/api/products");
const message = document.querySelector("#product-message");
const list = document.querySelector("#product-list");
list.innerHTML = "";

console.log(response.status);

if (!response.ok) {
  const problem = await response.json();
  message.textContent = problem.message;
  console.log(problem.message);
  return;
}

const products = await response.json();
message.textContent = products.length + " products";

for (const product of products) {
  const card = document.createElement("article");
  card.className = "product-card";

  const title = document.createElement("h3");
  title.textContent = product.name;

  const meta = document.createElement("p");
  meta.textContent =
    product.categoryName +
    " · " +
    product.price.toFixed(2) +
    " · " +
    product.stock +
    " in stock";

  card.append(title, meta);
  list.append(card);
}

console.log(products.length + " products rendered");

A page you can save

      
Copy this into shop.html, keep the API server running, and open the file in your browser. It works from your own folder because this API allows calls from other pages.

      


<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>My shop</title>
</head>
<body>
  <h1>Products</h1>
  <p id="message"></p>
  <ul id="products"></ul>
  <script>
    const API = "http://localhost:3000";

    async function loadProducts() {
      const message = document.querySelector("#message");
      const list = document.querySelector("#products");
      list.innerHTML = "";

      try {
        const response = await fetch(API + "/api/products");

        if (!response.ok) {
          const problem = await response.json();
          message.textContent = problem.message;
          return;
        }

        const products = await response.json();
        message.textContent = products.length + " products";

        for (const product of products) {
          const item = document.createElement("li");
          item.textContent =
            product.name + " — " + product.price + " (" + product.stock + " in stock)";
          list.appendChild(item);
        }
      } catch (error) {
        message.textContent = "Could not reach the API. Is the server running?";
      }
    }

    loadProducts();
  </script>
</body>
</html>

        

          
        

      

    


    

      
Mistakes that waste an hour

      
    
        
  • A 404 does not throw. Check response.ok before you treat the JSON as a product or a list.
    • 
        
  • fetch throws when the address is wrong or the server is stopped. That is the catch branch.
    • 
        
  • Forgetting Content-Type: application/json gives you 415.
    • 
        
  • Sending "12.50" instead of 12.5 gives you 400. Use Number(input.value).
    • 
        
  • Calling response.json() twice, or calling it on a 204, fails. Read the body once, and skip it when the status is 204.
    • 
        
  • PUT replaces the whole category or product. PATCH, which this API uses for reservations, sends only the changes.
    • 
        
  • Your new products disappear when the server restarts. That is expected. Use Reset, or restart, when you want the original shop back.
